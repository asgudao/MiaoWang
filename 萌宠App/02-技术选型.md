# 萌宠 App - 技术选型

## 前端：uni-app

### 选型理由

| 维度 | 优势 |
|---|---|
| 跨端能力 | iOS + Android + 微信小程序一次编写 |
| 学习曲线 | Vue 3 + TypeScript，背景熟悉 |
| 生态 | DCloud 插件市场 + uni-ui + uView Plus 成熟 |
| **vibe coding 友好度** | Vue 是 LLM 训练数据最多语言之一，Trae / Claude 生成质量最高 |
| 打包 | HBuilderX 一键云打包（iOS / Android / 小程序） |

### 技术栈

- **核心**：Vue 3 + `<script setup>` + TypeScript
- **构建**：Vite
- **UI 库**：uni-ui（官方） / uView Plus（社区）
- **状态管理**：Pinia
- **HTTP**：uni.request + 拦截器（详见"前后端通信"小节）
- **路由**：uni-app 内置 pages.json

### 风险 & 兜底

- iOS WebView 渲染偶尔不一致
- 原生能力调用（相机 / 推送 / 订阅支付）需人盯
- **Fallback**：若 vibe coding 解决不了兼容问题，退到原生 Kotlin Android

## 后端：Spring Boot

### 选型理由

- 求职向：Java 是 MapleLeaf 主攻方向
- 生态成熟：Java + Spring 是 LLM 训练数据最多的后端栈
- 学习成本低：MapleLeaf 已有 Java 基础

### 技术栈

- **核心**：Spring Boot 3.x
- **持久化**：MyBatis-Plus + MySQL 8
- **缓存**：Redis
- **鉴权**：JWT + Spring Security
- **对象存储**：腾讯云 COS / 阿里云 OSS（图片）
- **推送**：uniPush（uni-app 官方推送）
- **支付**：微信支付 + 支付宝（订阅档位）

### 模块划分（思路层）

```
com.mapleleaf.petapp
├── user/          # 用户、登录、JWT
├── pet/           # 宠物档案、品种库
├── knowledge/     # 知识库（CRUD + 搜索）
├── subscription/  # 订阅、支付、限只数校验
├── reminder/      # 提醒规则、推送
├── ai/            # AI Agent 接口（Phase 2）
└── community/     # 社区（Phase 3）
```

## AI 模型（Phase 2）

### 选型思路

- **国内多模态大模型**（性价比 + 合规）
- 候选：智谱 GLM-4V / 通义 Qwen-VL / 豆包视觉

### 接入方式

- 后端封装 `AIService` 接口
- 三个模型实现可切换（按场景路由：图片 → GLM-4V，文本 → Qwen）
- 调用量记录 + 配额管理（用于"试用 3-4 次"逻辑）

## 开发工具链（三端分工）

| 工具 | 角色 | 用途 |
|---|---|---|
| **Trae** | 前端主力 IDE | vibe coding（Vue/TS 代码生成）、日常编码 |
| **HBuilderX** | 前端辅助 IDE | 真机调试、云打包出 .apk / .ipa |
| **IntelliJ IDEA** | 后端主力 IDE | Spring Boot 后端开发、调试、启动 |
| DataGrip | 数据库客户端 | MySQL 客户端连接、查询 |
| 微信开发者工具 | 小程序调试 | 微信小程序端预览 / 上传 |

### 协作流程

```
日常开发（90% 时间）：
  Trae（前端代码）  ──┐
                       ├── Git 仓库同步
  IDEA（后端代码）   ──┘
                       │
  本地联调            ◀──┘  前端 dev proxy 转发 /api/* 到后端

真机调试 / 打包：
  Trae 写完 → commit → HBuilderX 拉取 → 真机预览 / 云打包
```

## 前后端通信

| 项 | 选型 |
|---|---|
| 协议 | **HTTPS / HTTP**（REST 风格） |
| 数据格式 | JSON |
| 鉴权 | JWT（前端拦截器自动加 Authorization 头） |
| 前端 HTTP 客户端 | `uni.request()`（uni-app 内置）+ 拦截器 |
| 后端 | Spring Web MVC（`@RestController` + `@RequestMapping`） |
| API 文档 | SpringDoc OpenAPI / Knife4j |

### API 风格示例

```
GET    /api/pets              → 列出当前用户的宠物
POST   /api/pets              → 新建宠物
GET    /api/pets/{id}         → 宠物详情
PUT    /api/pets/{id}         → 更新宠物
DELETE /api/pets/{id}         → 删除宠物
POST   /api/auth/login        → 登录，返回 JWT
POST   /api/subscription/order → 创建订阅订单
```

## 部署架构

> ⚠️ **关键概念**：HBuilderX 打包的是**前端**（uni-app 代码），**不打后端**。后端必须独立部署到云服务器。

### 三层结构

```
┌────────────────────────────────────┐
│     用户手机（.apk / .ipa）        │
│  ┌──────────────────────────────┐  │
│  │  uni-app 前端                  │  │
│  │  + uni-app runtime            │  │
│  │  + uni.request 调用后端        │  │
│  └──────────────────────────────┘  │
└──────────────────┬─────────────────┘
                   │ HTTPS（公网）
                   ↓
       ┌──────────────────────┐
       │  云服务器 / Docker    │
       │  Spring Boot 后端     │
       │  （独立 jar 部署）     │
       └──────┬───────────────┘
              ↓
       ┌─────────────┐
       │ MySQL+Redis │
       └─────────────┘
```

### 部署分工

| 层 | 谁来打包 / 部署 |
|---|---|
| 前端（uni-app） | HBuilderX 云打包 → .apk / .ipa |
| 后端（Spring Boot） | `java -jar xxx.jar` / Docker 容器（云服务器） |
| 数据库 | 云数据库 RDS 或自建 MySQL |
| 图片存储 | 腾讯云 COS / 阿里云 OSS |
| 域名 + HTTPS | 域名服务商 + Let's Encrypt / 云厂商证书 |
| API 域名 | 形如 `https://api.mengchongapp.com` |

### 上线阶段流程

```
1. 后端上云：Java jar → 云服务器（公网 HTTPS）
2. 前端 baseURL 改为 https://api.xxx.com
3. HBuilderX 云打包 → .apk / .ipa
4. 上架：iOS App Store / 国内 Android 商店 / 微信小程序
```
